# Grid Subsystem Implementation Plan

## Overview

This document defines the architecture, responsibilities, public API, and implementation roadmap for the Grid subsystem.

The Grid subsystem provides a unified geometric and topological representation of all supported grid types.

Supported grid sources may include:

* Cartesian grids
* Corner-point grids
* Voronoi / PEBI grids
* Tetrahedral grids
* Polyhedral grids
* GRDECL files
* Eclipse grid files
* VTK / VTU files
* Gmsh meshes
* Other mesh formats

The Grid subsystem must be completely independent from:

* Reservoir state
* Rock properties
* Fluid properties
* Wells
* Relative permeability
* Capillary pressure
* Transmissibility calculations
* Pressure solvers
* Transport solvers

The Grid subsystem owns only geometry and topology.

---

# Design Goals

## Primary Goals

* Single grid representation for all mesh types.
* Grid-type agnostic simulator.
* Immutable grid objects.
* Strong separation of concerns.
* Easy future extension.
* Industry format compatibility.
* Efficient geometry queries.
* Efficient face-based assembly support.

---

## Non Goals

The Grid subsystem will not:

* Store porosity.
* Store permeability.
* Store saturations.
* Store pressures.
* Store fluid properties.
* Store transmissibilities.
* Store well information.

These belong to other subsystems.

# Core Philosophy

Everything in the simulator should consume a Grid.

Nothing should care whether the Grid originated from:

```text
Cartesian
Corner Point
Voronoi
Polyhedral
GRDECL
VTK
```

The simulator only sees:

```python
Grid
```

---

# Grid Class

The Grid class is the central geometry object.

The class should be immutable.

Example:

```python
@dataclass(
    slots=True,
    frozen=True,
)
class Grid:
    ...
```

After construction the geometry must never change.

Any operation that modifies geometry should return a new Grid.

---

# Grid Construction

Users should rarely construct Grid directly.

Most construction should occur through:

```python
CartesianGridFactory
CornerPointGridFactory
VoronoiGridFactory
```

or through import functions.

However direct construction must still be supported.

# Architectural Rule

The Grid subsystem defines geometry and topology.

Everything else in the simulator must be built on top of it.

No simulation component may assume:

```python
pressure[i, j, k]
```

or any other structured indexing scheme.

All simulator components must operate using:

```python
cell_index
face_index
neighbor_connectivity
```

provided by the Grid object.

This guarantees compatibility with all future grid types without requiring solver rewrites.
